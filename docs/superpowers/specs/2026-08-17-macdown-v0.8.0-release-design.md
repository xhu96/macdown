# MacDown v0.8.0 Release Design

## Goal

Publish the first release of `xhu96/macdown` as `v0.8.0`, targeting commit
`9aba4a40f60c023e3375ad9c7337de5ffaa6005d`, with GitHub-generated source
archives and an explicitly unsigned/not-notarized universal DMG.

## Constraints

- The application version is `0.8.0`, matching `Tools/version.txt`.
- The release target remains the existing `master` commit; packaging support
  must not change the tagged source tree.
- The DMG is ad-hoc signed only. Release notes must state that it is not signed
  with Developer ID and is not notarized, so macOS Gatekeeper may block a
  normal double-click launch.
- The application must contain both `arm64` and `x86_64` slices and retain the
  macOS 11.0 deployment target.
- The release must not be published unless the remote build and artifact
  verification succeed.

## Architecture

Create an isolated branch named `codex/release-v0.8.0` from the release commit.
That branch adds a push-triggered GitHub Actions workflow used only as a remote
macOS/Xcode builder. The workflow checks out submodules, installs the pinned
Ruby/CocoaPods dependencies, builds the native parser dependency, resolves the
Xcode workspace, forces the application metadata to version `0.8.0`, archives
a universal Release build with ad-hoc signing, and packages the app plus an
`Applications` symlink into `MacDown-0.8.0-unsigned.dmg`.

The workflow verifies the bundle before uploading it: `codesign --verify`,
`lipo -archs`, `plutil` version checks, DMG verification, mount-and-inspect, and
SHA-256 generation. The downloaded artifact is checked again locally. Only then
is tag `v0.8.0` created at the unchanged `master` release commit and a public
GitHub Release created with the DMG and checksum attached. GitHub supplies the
standard source ZIP and tarball automatically from the tag.

## Failure Handling

- A dependency, archive, signing, architecture, version, or DMG check failure
  stops the workflow before artifact upload.
- A failed or incomplete artifact blocks tag and release creation.
- If the project cannot build on the selected hosted Xcode image, adjust only
  the isolated workflow branch and rerun; do not move or create the release tag.
- If the release interface cannot be reached from the available authenticated
  tools, preserve the verified DMG and report the precise publication blocker
  rather than publishing a partial release.

## Release Notes Contract

The release notes summarize the universal macOS 11+ modernization, Sparkle 2,
modern Xcode settings, Albanian localization, and dependency refresh. They also
contain a prominent unsigned/not-notarized warning and identify the exact source
commit. The attached checksum file allows download verification.

## Acceptance Criteria

1. The workflow completes successfully on a GitHub-hosted macOS runner.
2. The app reports `CFBundleShortVersionString` `0.8.0`.
3. The main executable reports both `arm64` and `x86_64` architectures.
4. Ad-hoc bundle verification passes, while no claim of Developer ID signing or
   notarization is made.
5. `hdiutil verify` passes and the mounted DMG contains `MacDown.app` plus the
   `Applications` symlink.
6. The public release is tagged `v0.8.0`, points to the intended commit, and
   contains the DMG, checksum, and GitHub-generated source archives.
